# Smart Expense Tracker

Smart Expense Tracker is a full-stack personal finance app with AI and automation.

## Overview

- Track expenses with categories, dates, and descriptions
- Manage monthly budgets
- View analytics (monthly summary, category breakdown, forecast)
- Use AI chat grounded with retrieval-augmented context (RAG), synced in real time at per-expense, daily, and monthly granularity
- Run automation workflows through n8n (e.g., receipt ingest, alerts, reports, nightly embedding self-heal)
- Connect any real MCP client (Claude Desktop, Claude Code, etc.) directly to the backend's tools over the Model Context Protocol

## Tech Stack

- Backend: FastAPI, SQLAlchemy, Alembic
- Database: PostgreSQL + pgvector
- Frontend: React + Vite
- AI tool access: Model Context Protocol (`mcp` Python SDK), OpenAI-compatible function calling
- Automation: n8n
- Deployment: Render Blueprint (`render.yaml`)

## 5) Deploy on Render

This repository includes `render.yaml` for a Render Blueprint deployment.

### Deploy steps

1. Push this repository to GitHub.
2. In Render, click **New +** -> **Blueprint**.
3. Select this repository.
4. Render will create:
	- `smart-expense-db` (managed PostgreSQL)
	- `smart-expense-backend` (FastAPI)
	- `smart-expense-frontend` (static site)
5. In Render dashboard, set backend secrets:
	- `LLM_API_KEY` (your real provider key)
6. After first deploy, update URLs:
	- Backend `CORS_ORIGINS` to your real frontend URL
	- Frontend `VITE_API_BASE_URL` to your real backend URL + `/api/v1`
7. Redeploy backend and frontend services.

### Notes

- `JWT_SECRET_KEY` and `AUTOMATION_API_KEY` are generated by Render from `render.yaml`.
- `DATABASE_URL` is automatically wired from the managed Render database.
- Keep real secrets only in environment variables (never in tracked files).
- Migrations run as a `preDeployCommand`, separate from `startCommand`, so a bad migration never leaves the service with zero healthy instances.

### Troubleshooting: `psycopg.OperationalError: [Errno -2] Name or service not known`

This means DNS resolution of the database host failed -- `DATABASE_URL` points
at a hostname that no longer resolves. Ranked by likelihood:

1. **The free Postgres database expired and was deleted.** Render deletes free-tier Postgres databases 30 days after creation. Check the Render dashboard under Databases -- if `smart-expense-db` is gone or shows "expired," recreate it (or upgrade to a paid plan) and let the blueprint's `fromDatabase` re-wire `DATABASE_URL`.
2. **`DATABASE_URL` was manually overridden** on the backend service (bypassing `fromDatabase`). Check the service's Environment tab; remove any manual override so the blueprint-managed value takes over again.
3. **Region mismatch** -- the database's internal hostname only resolves to services in the same Render region. Confirm the backend and database services are in the same region.

Optional frontend env:

- `VITE_API_BASE_URL` (default: `http://localhost:8000/api/v1`)

## Phase 1 Notes

- Auth, expenses, budgets, and analytics endpoints are available in the backend.
- AI chat endpoint is available at `POST /api/v1/ai/chat` (requires `LLM_API_KEY` in backend `.env`).
- RAG embeddings sync automatically on every expense write (per-expense, daily, and monthly summaries). Manual controls: `POST /api/v1/ai/embeddings/rebuild` (current month) and `POST /api/v1/ai/embeddings/backfill` (full history, for pre-existing data).
- A real MCP server is mounted at `/mcp` -- see "Connecting an MCP Client" below.
- n8n automation endpoints are available under `/api/v1/automation/*` with `X-Automation-Key` header.
- Frontend Phase 6 pages are implemented: Login/Register, Dashboard, Expenses, Budgets, and AI Chat.

## Connecting an MCP Client

The backend exposes `add_expense`, `get_category_summary`, and
`forecast_end_of_month` as real [Model Context Protocol](https://modelcontextprotocol.io)
tools over streamable-HTTP at `/mcp/` (e.g. `http://localhost:8000/mcp/`
locally). This is separate from the in-app AI chat -- it lets any
MCP-compatible client (Claude Desktop, Claude Code, etc.) call these tools
directly, authenticated as a specific user.

Every call requires `Authorization: Bearer <token>`, using the same JWT
`POST /api/v1/auth/login` returns. Example with Claude Code:

```powershell
claude mcp add --transport http expense-tracker http://localhost:8000/mcp/ --header "Authorization: Bearer <your-jwt>"
```

Check your client's own docs for its exact syntax for adding an HTTP MCP
server with a custom header.
